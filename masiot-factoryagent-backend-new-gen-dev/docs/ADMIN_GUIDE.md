# Руководство администратора

## 1. Управление пользователями

### 1.1. Доступ к разделу

Раздел «Пользователи» доступен только для роли `admin`. Нажмите на пункт «👥 Пользователи» в боковом меню (под аватаром администратора).

### 1.2. Создание пользователя

1. Нажмите кнопку **Добавить пользователя**.
2. Заполните форму:
   - **Логин** — уникальное имя (только латиница, цифры, `_`).
   - **Пароль** — минимум 6 символов.
   - **Роль** — `admin` (полный доступ) или `user` (обычный пользователь).
   - **ФИО** — отображаемое имя.
3. Нажмите **Сохранить**.

**Важно:** пароль автоматически хешируется алгоритмом BCrypt и шифруется AES-256 для возможности просмотра администратором.

### 1.3. Редактирование и удаление

- Двойной клик по строке в таблице — редактирование.
- Кнопка 🗑️ — удаление (с подтверждением).

### 1.4. Миграция паролей

Если система обновляется со старой версии (до внедрения BCrypt), выполните:

```bash
curl -X POST http://localhost:3001/api/admin/migrate-passwords \
  -H "X-API-Key: monitoring_secret_key_12345678"
```

Это создаст `password_hash` (BCrypt) для всех пользователей у которых есть только `password` (AES).

## 2. Управление словарём параметров

### 2.1. Зачем нужен словарь

Словарь параметров — единый реестр возможных характеристик агентов. При сохранении параметров агента уникальные имена автоматически попадают в словарь (начиная с текущей версии backend).

### 2.2. CRUD операции

Откройте **Настройки** (⚙️) → вкладка **Словарь параметров**.

| Действие | Описание |
|----------|----------|
| Добавить | Имя, описание, тип (`string` / `number` / `yes-no`), единица измерения |
| Редактировать | Двойной клик по строке |
| Удалить | Кнопка 🗑️ |

**Типы параметров:**
- `string` — текстовое значение (по умолчанию).
- `number` — числовое значение.
- `yes-no` — логическое (да/нет).

### 2.3. Автоматическое наполнение

При сохранении параметров агента через `AgentPage` → «Сохранить параметры» backend автоматически добавляет новые имена в словарь с типом `string`. Администратор может позже изменить тип и описание вручную.

## 3. Управление ОКПД-2

### 3.1. Полный классификатор

Таблица `okpd2_dictionary` содержит иерархический классификатор ОКПД-2. Заполняется автоматически при инициализации БД (`schema.sql`).

### 3.2. Маппинг заготовок

Вкладка **Справочник ОКПД-2** в Настройках (доступна только `admin`).

**Зачем нужен:** при создании агента типа `blank` система автоматически подбирает код ОКПД-2 по названию заготовки на основе этого маппинга.

**Операции:**
- Просмотр всех пар «ключевое слово → код».
- Добавление новой пары.
- Редактирование описания.
- Удаление.

**Массовая загрузка:**
```bash
curl -X POST http://localhost:3001/api/blank-okpd2/bulk-upsert \
  -H "Content-Type: application/json" \
  -d '{"items": [
    {"keywords": "Вал ступенчатый", "okpd2Code": "25.73.40.130", "description": "..."},
    {"keywords": "Корпус", "okpd2Code": "25.73.40.190", "description": "..."}
  ]}'
```

## 4. Мониторинг и диагностика

### 4.1. Логи backend

Файлы расположены в `Backend/logs/`:
- `backend-YYYYMMDD.log` — ежедневные логи Serilog.
- `backend.log` — текущий лог.

Формат: JSON/текст с уровнями `INF`, `WRN`, `ERR`.

### 4.2. API мониторинга

Все endpoint'ы требуют заголовок `X-API-Key` (значение из `appsettings.json` → `MonitoringApiKey`).

| Endpoint | Описание | Пример |
|----------|----------|--------|
| `GET /api/monitoring/statistics` | Статистика по типам агентов | `curl -H "X-API-Key: ..." http://localhost:3001/api/monitoring/statistics` |
| `GET /api/monitoring/users` | Список пользователей с ролями | — |
| `POST /api/monitoring/decrypt` | Расшифровка AES-пароля | `curl -X POST -H "X-API-Key: ..." -d '{"encryptedPassword":"..."}' http://localhost:3001/api/monitoring/decrypt` |

### 4.3. RabbitMQ Management UI

Откройте `http://localhost:15672` (логин/пароль: `guest`/`guest`).

**Что проверять:**
- **Connections** — активные соединения backend.
- **Queues** — очередь `backend_queue` (должна быть пустой при штатной работе).
- **Exchanges** — exchange `topic_logs` (тип `topic`).

## 5. Резервное копирование и восстановление

### 5.1. База данных

**Резервное копирование:**
```bash
pg_dump -U postgres -d agenti_db > backup_$(date +%Y%m%d_%H%M%S).sql
```

**Восстановление:**
```bash
psql -U postgres -c "CREATE DATABASE agenti_db_restore;"
psql -U postgres -d agenti_db_restore < backup_20260530_120000.sql
```

### 5.2. Файлы проекта

Сохраните:
- `Backend/appsettings.json` (конфигурация, ключи шифрования).
- `.env` (если используется).
- Все файлы в `docs/` и `scripts/`.

## 7. Безопасность

### 7.1. Смена ключей шифрования

**Внимание:** ключи в `appsettings.json` должны быть заменены на production.

1. Сгенерируйте новый AES-ключ (256 бит) и IV.
2. Обновите `Backend/appsettings.json`:
   ```json
   "Encryption": {
     "Key": "YOUR_NEW_BASE64_KEY_HERE",
     "IV": "YOUR_NEW_HEX_IV_HERE"
   }
   ```
3. Перезапустите backend.
4. **Важно:** существующие зашифрованные пароли станут недоступны — потребуется ручная смена паролей всех пользователей.

### 7.2. Смена API-ключа мониторинга

```json
"MonitoringApiKey": "your_new_secret_key_min_16_chars"
```

### 7.3. CORS

В `Backend/Program.cs` политика `AllowFrontend` разрешает `localhost`. Для production ограничьте конкретными доменами:

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
    {
        policy.WithOrigins("https://your-domain.com")
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials();
    });
});
```

## 8. Устранение неисправностей

### 8.1. Backend не запускается

| Симптом | Причина | Решение |
|---------|---------|---------|
| `BrokerUnreachableException` | RabbitMQ не запущен | Запустите службу RabbitMQ |
| `Authentication failed` | Неверный пароль PostgreSQL | Проверьте `appsettings.json` и пароль пользователя `postgres` |
| `relation does not exist` | БД не инициализирована | Накатите `schema.sql` |

### 8.2. Frontend не подключается к API

| Симптом | Причина | Решение |
|---------|---------|---------|
| `CORS policy` | Неправильный origin | Проверьте URL frontend в `Program.cs` |
| `Connection refused` | Backend не запущен | Запустите `dotnet run` в папке `Backend` |
| `404 Not Found` | Неправильный base URL | Проверьте `VITE_API_URL` или хардкод в `api.js` |

### 8.3. Workflow не выполняется

1. Проверьте логи backend на ошибки Reflection.
2. Убедитесь, что все функции шаблона есть в whitelist (`WorkflowFunctionWhitelist`).
3. Проверьте параметры workflow — должны соответствовать типам.

## 9. Контакты и поддержка

При критических ошибках:
1. Соберите логи из `Backend/logs/`.
2. Сделайте дамп БД.
3. Зафиксируйте версию кода (`git log --oneline -5`).
4. Обратитесь к техническому специалисту с этими данными.
