## 📋 Шаги для запуска (выполните по порядку)

### Шаг 1: Миграция базы данных
```bash
cd d:\Masiot
psql -U postgres -d agenti_db -f migrations/add_okp_cache_table.sql
```

**Ожидаемый результат:**
```
✓ Таблица okp_cache успешно создана
```

### Шаг 2: Настройка Backend

1. Скопируйте пример конфигурации (если ещё не сделано):
```bash
cd Backend
copy appsettings.Example.json appsettings.json
```

2. Откройте `Backend/appsettings.json` и добавьте/обновите секцию:
```json
{
  "OkpApi": {
    "BaseUrl": "https://api.okp.example.ru/v1",
    "TimeoutSeconds": 30
  }
}
```

**⚠️ ВАЖНО:** Замените `https://api.okp.example.ru/v1` на реальный URL API!

### Шаг 3: Установка зависимостей Backend
```bash
cd Backend
dotnet restore
```

### Шаг 4: Запуск Backend
```bash
cd Backend
dotnet run
```

**Проверка:** Backend должен запуститься на http://localhost:3001

### Шаг 5: Установка зависимостей Frontend
```bash
cd d:\Masiot
npm install
```

### Шаг 6: Запуск Frontend
```bash
npm run dev
```

**Проверка:** Frontend должен запуститься на http://localhost:5173

## 🧪 Тестирование

### Тест 1: Проверка Backend API
```bash
# Проверка здоровья
curl http://localhost:3001/api/health

# Статистика кэша (должен вернуть totalCached: 0 при первом запуске)
curl http://localhost:3001/api/okp/cache-stats
```

### Тест 2: Первое обновление кэша (для администратора)

1. Откройте http://localhost:5173
2. Войдите как администратор:
   - Логин: `admin`
   - Пароль: `admin`
3. Нажмите ⚙️ Настройки
4. Перейдите на вкладку "Кэш ОКП (Администратор)"
5. Нажмите "Обновить кэш вручную"
6. Дождитесь завершения (может занять несколько минут)

### Тест 3: Создание агента с автопоиском ОКП

1. Перейдите в любую папку (например, "Токарный цех")
2. Перейдите на вкладку "Параметры"
3. В поле "Имя агента" начните вводить: `Токарный станок`
4. Подождите 500мс
5. **Ожидаемый результат:**
   - Появится "Поиск ОКП..."
   - Затем поле ОКП автоматически заполнится
   - Поле станет read-only (серый фон)

### Тест 4: Импорт XLSX с автопоиском

1. Перейдите на главную страницу
2. Загрузите XLSX файл с оборудованием
3. **Ожидаемый результат:**
   - Для агентов без ОКП в файле система автоматически найдёт коды
   - В консоли браузера (F12) будут логи поиска ОКП

### Тест 5: Просмотр агента

1. Откройте любого созданного агента
2. Перейдите на вкладку "Инфо"
3. **Ожидаемый результат:**
   - Поле "ОКП" отображается
   - Значение взято из API

## 🐛 Устранение проблем

### Проблема: "Таблица okp_cache не существует"
**Решение:** Выполните миграцию из Шага 1

### Проблема: "ОКП не найден" при создании агента
**Причины:**
1. API недоступен - проверьте URL в appsettings.json
2. Кэш пустой - обновите кэш вручную (Тест 2)
3. Неправильное название - попробуйте другое название оборудования

**Проверка:**
```bash
# Проверьте доступность API
curl https://api.okp.example.ru/v1/health

# Проверьте логи Backend
cat Backend/logs/backend-*.log | grep -i "okp"
```

### Проблема: Кнопка "Обновить кэш" не работает
**Причины:**
1. Вы не администратор - войдите как admin
2. API недоступен - проверьте URL
3. Timeout - увеличьте TimeoutSeconds в конфигурации

### Проблема: Медленный поиск ОКП
**Решение:**
1. Проверьте индексы в БД: `\d okp_cache`
2. Увеличьте TimeoutSeconds до 60
3. Проверьте производительность внешнего API
