# Интеграция ОКП API - Инструкция по внедрению

## Обзор изменений

Система теперь автоматически получает коды ОКП из государственного API классификатора вместо ручного ввода.

## Что изменилось

### Backend

1. **Новые сервисы:**
   - `IOkpApiService` / `OkpApiService` - интеграция с API ОКП
   - `OkpCacheRefreshService` - автоматическое обновление кэша раз в 24 часа

2. **Новая модель:**
   - `OkpCacheEntry` - кэширование данных из API

3. **Новый контроллер:**
   - `OkpApiController` - REST API для работы с ОКП

4. **Endpoints:**
   - `GET /api/okp/search?name={name}` - поиск ОКП по названию оборудования
   - `GET /api/okp/code/{code}` - получение ОКП по коду
   - `POST /api/okp/refresh-cache` - ручное обновление кэша (только админ)
   - `GET /api/okp/cache-stats` - статистика кэша

### Frontend

1. **BranchPage:**
   - Автоматический поиск ОКП при вводе названия оборудования
   - Поле ОКП становится read-only если найден один результат
   - Выпадающий список если найдено несколько вариантов

2. **SettingsModal:**
   - Удалена вкладка "Создать новый ОКП" для обычных пользователей
   - Для администраторов: вкладка "Кэш ОКП" со статистикой и кнопкой обновления

3. **AgentPage:**
   - Поле ОКП отображается как read-only (не редактируется)

## Шаги по внедрению

### 1. Обновление базы данных

```bash
# Выполните миграцию для создания таблицы okp_cache
psql -U postgres -d agenti_db -f migrations/add_okp_cache_table.sql
```

### 2. Настройка конфигурации

Обновите `Backend/appsettings.json`:

```json
{
  "OkpApi": {
    "BaseUrl": "https://api.okp.example.ru/v1",
    "TimeoutSeconds": 30
  }
}
```

**ВАЖНО:** Замените `https://api.okp.example.ru/v1` на реальный URL API классификатора ОКП.

### 3. Перезапуск приложения

```bash
# Backend
cd Backend
dotnet restore
dotnet run

# Frontend (в новом терминале)
npm install
npm run dev
```

## Как это работает

### Для пользователей

1. **Создание агента:**
   - Пользователь вводит название оборудования (например, "Токарный станок 16K20")
   - Система автоматически ищет ОКП в API через 500мс после окончания ввода
   - Если найден один ОКП - он автоматически выбирается и поле блокируется
   - Если найдено несколько - пользователь выбирает из списка
   - Если не найдено - показывается предупреждение

2. **Просмотр агента:**
   - Поле "Код ОКП" отображается как read-only
   - Изменить ОКП нельзя (данные из API)

### Для администраторов

1. **Управление кэшем:**
   - Настройки → Кэш ОКП (Администратор)
   - Просмотр статистики: количество записей, последнее обновление
   - Кнопка "Обновить кэш вручную" для принудительного обновления

2. **Автоматическое обновление:**
   - Кэш обновляется автоматически раз в 24 часа
   - При первом запуске обновление происходит через 1 минуту

## Логика работы

### Поиск ОКП

1. Пользователь вводит название оборудования
2. Frontend отправляет запрос: `GET /api/okp/search?name=Токарный станок`
3. Backend:
   - Ищет в локальном кэше (okp_cache)
   - Если не найдено - запрашивает из внешнего API
   - Сохраняет результат в кэш
   - Возвращает список найденных ОКП

### Кэширование

- **Локальный кэш:** PostgreSQL таблица `okp_cache`
- **Время жизни:** 24 часа
- **Обновление:** автоматически раз в сутки + ручное обновление админом
- **Офлайн режим:** если API недоступен, используются данные из кэша

### Автозапрос при новом коде

Если в системе появляется агент с ОКП, которого нет в кэше:
- При следующем автоматическом обновлении (раз в 24 часа) система запросит все уникальные ОКП из таблицы `agents`
- Новые коды будут добавлены в кэш

## Устранение проблем

### API недоступен

**Симптом:** Ошибка "ОКП не найден" при создании агента

**Решение:**
1. Проверьте URL API в `appsettings.json`
2. Проверьте доступность API: `curl https://api.okp.example.ru/v1/health`
3. Проверьте логи Backend: `logs/backend-*.log`

### Кэш не обновляется

**Симптом:** Старые данные в кэше

**Решение:**
1. Проверьте, запущен ли `OkpCacheRefreshService` в логах
2. Вручную обновите кэш через админ-панель
3. Проверьте таблицу: `SELECT COUNT(*), MAX(cached_at) FROM okp_cache;`

### Медленный поиск

**Симптом:** Долгий ответ при поиске ОКП

**Решение:**
1. Проверьте индексы: `\d okp_cache` в psql
2. Увеличьте `TimeoutSeconds` в конфигурации
3. Проверьте производительность API

## Откат изменений

Если нужно вернуться к старой системе:

```sql
-- Удалить таблицу кэша
DROP TABLE IF EXISTS okp_cache CASCADE;

-- Вернуть старые данные ОКП (если были сохранены)
-- Таблица okp_dictionary не удалялась, данные остались
```

Затем откатите код до предыдущей версии.
