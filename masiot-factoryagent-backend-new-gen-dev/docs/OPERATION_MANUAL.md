# Инструкция по эксплуатации

## 1. Ежедневные операции

### 1.1. Запуск системы

**Если используется Docker:**
```bash
docker-compose up -d
```

**Если используется локальный запуск:**
```bash
# Терминал 1 — Backend
cd Backend
dotnet run --urls "http://localhost:3001"

# Терминал 2 — Frontend
cd <корень проекта>
npm run dev
```

**Проверка работоспособности:**
- Frontend: откройте `http://localhost:5173`, авторизуйтесь.
- Backend: `curl http://localhost:3001/api/tree` должен вернуть JSON.
- RabbitMQ: `http://localhost:15672` должен открывать Management UI.

### 1.2. Остановка системы

**Docker:**
```bash
docker-compose down
```

**Локальный запуск:**
- Backend: `Ctrl + C` в терминале.
- Frontend: `Ctrl + C` в терминале.

## 2. Мониторинг состояния

### 2.1. Проверка компонентов

| Компонент | Команда проверки | Норма |
|-----------|------------------|-------|
| PostgreSQL | `pg_isready -h localhost -p 5432` | `accepting connections` |
| RabbitMQ | `curl -s http://localhost:15672/api/overview -u guest:guest` | HTTP 200 |
| Backend | `curl -s http://localhost:3001/api/tree` | HTTP 200, JSON |
| Frontend | `curl -s http://localhost:5173` | HTTP 200, HTML |

### 2.2. Просмотр логов в реальном времени

**Backend (PowerShell / Git Bash):**
```bash
tail -f Backend/logs/backend.log
```

**Docker:**
```bash
docker-compose logs -f backend
docker-compose logs -f frontend
```

### 2.3. Метрики RabbitMQ

Веб-интерфейс: `http://localhost:15672`

**Критические индикаторы:**
- `backend_queue` — если растёт, значит обработчик сообщений не справляется.
- `Connection` — должен быть хотя бы 1 (от backend).

## 3. Управление пользователями и доступом

### 3.1. Смена пароля администратора

1. Войдите как `admin`.
2. Перейдите в «👥 Пользователи».
3. Найдите свою учётную запись, нажмите для редактирования.
4. Введите новый пароль, сохраните.

### 3.2. Блокировка пользователя

На данный момент система не поддерживает явную блокировку. Для запрета доступа:
- Удалите пользователя.
- Или измените его роль на несуществующую (временное решение).

## 4. Управление данными

### 4.1. Добавление нового агента

1. В дереве выберите ветку (папку).
2. Перейдите на вкладку «Параметры».
3. Заполните форму создания агента.
4. Нажмите **Создать агента**.

### 4.2. Редактирование параметров агента

1. Откройте карточку агента.
2. Измените значения в таблице параметров.
3. Нажмите **Сохранить параметры**.

### 4.3. Удаление агента

1. Откройте карточку агента.
2. Нажмите **Удалить агента**.
3. Подтвердите удаление.

### 4.4. Импорт из Excel

1. Подготовьте `.xlsx` по шаблону (см. `USER_GUIDE.md`).
2. Перетащите файл на главную страницу.
3. Проверьте предпросмотр.
4. Нажмите **Создать агентов**.

---

## 5. Управление workflow

### 5.1. Запуск workflow

1. Откройте карточку агента → вкладка «Настройка Workflow».
2. Выберите шаблон из списка.
3. Нажмите **Отправить в RabbitMQ**.
4. Перейдите в Мониторинг workflow для отслеживания.

### 5.2. Продолжение после ошибки

1. Откройте Мониторинг workflow.
2. Найдите workflow со статусом **Ошибка**.
3. Нажмите **Продолжить**.
4. Укажите номер шага, с которого продолжить.

### 5.3. Создание нового шаблона

1. Откройте «🎨 Редактор шаблонов».
2. Перетащите функции из палитры на холст.
3. Соедините узлы рёбрами.
4. Введите название шаблона.
5. Нажмите **Сохранить**.

## 6. Резервное копирование

### 6.1. Автоматическое резервирование (рекомендуется)

Настройте `cron` (Linux) или Планировщик задач (Windows) на выполнение:

```bash
pg_dump -U postgres -d agenti_db > /backup/agenti_db_$(date +\%Y\%m\%d_\%H\%M\%S).sql
tar -czf /backup/masiot_$(date +\%Y\%m\%d).tar.gz /c/MASIOT/Backend/appsettings.json /c/MASIOT/docs/ /c/MASIOT/scripts/
```

### 6.2. Ручное резервирование

Выполните перед каждым обновлением системы:
```bash
pg_dump -U postgres -d agenti_db > backup_pre_update.sql
```

### 6.3. Хранение резервных копий

- Храните копии минимум 7 дней.
- Выносите копии на внешний носитель или облако.

## 7. Обновление системы

### 7.1. Подготовка

1. Уведомите всех активных пользователей.
2. Сделайте резервную копию БД.
3. Остановите backend и frontend.

### 7.2. Обновление кода

```bash
git pull origin main
# или распакуйте новую версию поверх старой
```

### 7.3. Применение миграций

```bash
cd Backend
dotnet ef database update
```

Если миграций нет, но изменилась схема — примените `schema.sql` вручную (осторожно, данные могут пострадать).

### 7.4. Пересборка

```bash
cd Backend
dotnet build

cd ..
npm install
npm run build
```

### 7.5. Запуск

```bash
# Docker
docker-compose up -d --build

# Локально
cd Backend && dotnet run --urls "http://localhost:3001"
cd .. && npm run dev
```

## 8. Устранение аварийных ситуаций

### 8.1. PostgreSQL перестал отвечать

**Симптом:** Все API возвращают 500.

**Действия:**
1. Проверьте службу:
   ```bash
   # Windows
   sc query postgresql-x64-16
   
   # Linux
   sudo systemctl status postgresql
   ```
2. Перезапустите:
   ```bash
   # Windows
   sc stop postgresql-x64-16 && sc start postgresql-x64-16
   
   # Linux
   sudo systemctl restart postgresql
   ```
3. Проверьте дисковое пространство.

### 8.2. RabbitMQ переполнен сообщениями

**Симптом:** Очередь `backend_queue` содержит тысячи сообщений.

**Действия:**
1. Откройте RabbitMQ Management UI.
2. Проверьте, что backend запущен и подключён.
3. При необходимости очистите очередь (⚠️ сообщения будут потеряны).

### 8.3. Frontend показывает пустое дерево

**Действия:**
1. Проверьте консоль браузера (F12 → Console).
2. Убедитесь, что backend отвечает: `curl http://localhost:3001/api/tree`.
3. Проверьте CORS-политику в `Backend/Program.cs`.
4. Обновите страницу (Ctrl + F5).

### 8.4. Workflow завис

**Действия:**
1. Проверьте логи backend.
2. Найдите workflow в Мониторинге.
3. Если статус `running` дольше ожидаемого — возможен deadlock в Reflection.
4. Перезапустите backend (workflow с `Task.Run` прервётся).
5. Продолжите workflow с последнего шага.

При критических сбоях:
1. Зафиксируйте время события.

3. Сделайте скриншоты ошибок.
4. Обратитесь к системному администратору или разработчику.
